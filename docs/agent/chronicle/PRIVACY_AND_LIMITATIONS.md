# Privacy, resource limits and remaining work

Debug Mode defaults off. Ordinary mode keeps only cheap status/provenance observations. Sanitization happens before diagnostic persistence: free titles, filenames, exception messages, credentials, cookies, headers, file bytes, DOM and physical paths are omitted or replaced with opaque references. URL diagnostics retain protocol/origin and an opaque reference; paths, userinfo, query and fragments do not survive. Only a closed vocabulary of safe action/mode/reason symbols is preserved verbatim. These references are lightweight obfuscation, not encryption or content identity; origins and correlation patterns can still reveal browsing history. Export requires an explicit user action and performs no automatic upload.

Chronicle interchange has a separate privacy boundary: normalized source pages/roles and optionally caller-supplied harmless title/name/destination metadata are useful recall data and remain potentially private history. Browser default capture omits title, filename and exact destination. Signed queries/fragments never survive, generated Blob references are not remotely retrievable, and unknown extra record fields are rejected. Keep execution URLs/tokens in their existing restricted execution stores, outside bundles. Neither recorder copies original local file contents.

Limits: diagnostics 2,000 events per API snapshot, 16 KiB per event, 4 MiB per bundle, 128 recorder pending slots, 256 sanitized detail nodes, depth six, 32 fields/items at a detail boundary, 16 causal links, 100 derived trace reports. Browser persistence retains 1,000 diagnostics and 500 metadata observations; retention truncation records an explicit gap. Large exports retain a bounded recent event subset and declare omitted-event/trace-report counts instead of blocking transfers. Host journals default to 32 MiB and one writer. Archive segments default to 200 events (max 500), restores at most 500 segments/100,000 events/50 MB. APIs page at most 200 results.

A storage failure can prevent its own error event from persisting. The still-running recorder exposes pending gap summaries, failure counts and bounded references; if that worker also disappears, the missing observations remain unknown. Browser memory/Chrome local storage/IndexedDB are erasable. File journals require real caller-provided durable disk, are not a cross-process locked database, and are not a Windows host. Append retries are bounded and not an indefinite durability promise.

Coverage gaps: installed Chrome and live R2 have not been tested; remote DNS/redirect/ETag/range/body events, gateway multipart/abort/binding internals, OAuth/provisioning/menu permission/profile outcomes, detailed page-world button/Blob lifecycle, local-upload/native sleep/restart/deletion, per-attempt remote tracing and imported executor traces are not integrated. The optional R2 adapter observer is tested through injection; normal executor configuration does not yet attach a diagnostic journal. No native companion, accepted Forever model, destructive cleanup or production R2 history vault exists. History import/recall and vault operations are library capabilities, not a complete owner-facing restore/search UI.

The minimal-to-rich provenance mapping is one-way and explicitly lossy. Cached recognition, equal size, URL or name never establishes byte equality, current remote existence or cleanup eligibility. Existing transfer readback verification retains its independent standard.
