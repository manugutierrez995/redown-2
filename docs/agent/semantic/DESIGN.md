# Format, authority and replacement

`agent/semantic/model.json` is a normalized plain UTF-8 semantic graph 0.1. `schemas/0.1/graph.schema.json` is the versioned structural contract; the Node assertion subset is checked against independent JSON Schema validation. Nodes distinguish project, intent, capability, invariant, operation, state transition, component, interface, dependency, evidence, test, incident, change, outcome, decision and lesson. These are **ReDown graph kinds**, not new Forever Works kinds. Source locations are replaceable evidence, never semantic identity.

IDs are globally scoped `redown.*`, lower-case exact strings using the Forever-compatible identifier alphabet. Exact lookup precedes aliases; aliases cannot collide with IDs or one another and point only to their owning entity. A rename keeps ID and changes located references with reviewed provenance. A split/merge creates new IDs and explicit typed edges/decision metadata, retains old entities with deprecated status and replacement candidates, and never silently redirects ambiguous identities. Missing endpoint, duplicate ID or alias collision invalidates the graph. Self-loops and cycles are valid; traversal uses visited sets and depth/node budgets. Stable IDs do not promise stable filenames or claim permanent completeness.

Edges have their own IDs, direction, type, rationale and provenance. Their reverse adjacency is computed from the same canonical edge; no duplicated reverse truth exists. `implements` connects a capability to its replaceable realization, `requires` to a contract, `calls` to an operation/interface, `verifies` to a suggested test, `affects` to an incident, `documents` to exact historical events and `generalizes` to a lesson. Supporting and contradicting claims remain separate links; conflicting evidence is retained rather than aggregated into an invented probability or pass. Causal graph proximity is a possible-impact heuristic, not independent causal proof.

Public artifact inventory lists path, semantic owner and coverage. Artifact identities remain locations; semantic owner IDs express continuity. All public source/test/doc/config/build/assets/debug files are addressable at file granularity; many behaviors have only partial reviewed topology. Private `.env` files and templates, credential paths, ignored generated trees, scratch files and symlinks are excluded from enumeration. The committed inventory is finite. Explicit validation warns about newly unlisted public files; developer `node agent/semantic/inventory.mjs --write` only updates path ownership, and must be reviewed. It does not refresh evidence hashes or establish behavior coverage. Source changes yield warnings until claims are re-inspected and individual anchors/digests intentionally reviewed.

The offline reader does not import extension code or execute referenced commands. Existing agent/debug APIs are used through their real library interfaces; no new operations are injected into frozen contracts. Debug descriptor/journal links are exact; original events retain chronology, source provenance, counterevidence and proof scopes. Journal file digests qualify a snapshot; individual event IDs retain their historical identity. Corrections append events and retain the old prefix. Matching a commit is never test/browser proof.

## Portable learning bridge

The MIT-licensed unmodified JavaScript reference and schemas are vendored from Forever Works `230c67fa7e27577c53b6f7895df442a2ab24e4cb` to allow independent offline checks. `vendor/forever-works-0.1/UPSTREAM.json` records paths and exact hashes. Upstream authority remains standard → schemas/conformance → bindings → tooling; vendoring does not alter it. Upstream main was not changed. The separate proposed correction is [Forever Works draft PR #5](https://github.com/thanks-cohn/forever-works/pull/5), commit `177c15ce3ede0f20fd16262c533db096c6875f86`. The vendored baseline remains byte-identical.

Export maps intent/capability/invariant/evidence/decision to actual kinds, components to implementation records, and a lesson to a **decision proposal**. Unsupported project-specific kinds are explicitly omitted from normative projection and retained in source-entity/edge extensions where relevant. Dependencies without a reviewed classification are omitted, rather than inventing an upstream dependency policy. Original source entity/provenance and directed links live below the owner-qualified `org.redown` extension. Exports always have `agent-proposed/unreviewed` provenance; no ordinary query accepts a record. Required upstream numeric confidence is 0 as an explicit conservative lower bound, not a measured probability. Requirements and mechanisms stay separate.

The exported request-context lesson covers account/bucket/parent ownership before any post-await shared-state write. Immutable snapshots and serialized requests are counterexamples to needing this guard; it does not prove provider correctness, authorization, pagination, transactional remote writes or browser outcomes. The existing root guard is counterevidence against overgeneralizing the child-cache defect.

**Compatibility blocker:** the pinned published record schemas use an overescaped `foreverVersion` regex that rejects the standard's own `0.1` examples. ReDown's proposal passes the actual upstream JavaScript model/API validator, but fails those published JSON Schemas on version alone. `exportLesson` therefore reports `blocked-by-published-schema`. The independently recorded schema result is a failure, even though the regression script successfully detects it. No fully conformant export or accepted ReDown Forever model is claimed. A separately reviewed upstream correction is needed. Draft PR #5 fixes the regex, with 21 JavaScript tests passing and 72 records independently validating against its proposed schemas. It is unmerged; those proposed results do not certify the pinned baseline.

## Upgrade, rollback and replacement evidence

Released 0.1 fixtures and semantic golden are archived under `tests/fixtures/semantic/0.1/`. Unknown optional fields round-trip. Unsupported format versions fail explicitly; no eager conversion occurs. `normalizeSnapshot(originalBytes)` retains the original bytes/digest and produces a sorted 0.1 representation with an auditable transform identity, normalized digest and unchanged authority. It is an opt-in in-memory transform and does not publish files. Incompatible future releases must add a separate decoder, preserve old fixtures and original digests, and document explicit transformations. Rollback restores graph/adapter together; frozen legacy APIs remain independently available.

Replacement tests compare the production adjacency walker with an independent repeated-relational-join representation across every fixture start/direction/depth, including a cycle. This demonstrates reader representation equivalence for the archived corpus, not universal equivalence or a production UI rewrite. The same semantic ID survives simulated source/language changes. Actual upstream replacement evaluation is `partial` with absent browser evidence and `fail` with a declared failed obligation; it never interprets fixture equivalence as installed-browser success. Output ordering, preservation of unknown fields and explicit truncation are tested. No memory benchmark on a physical 4 GB device or fleet-scale trial was performed.
